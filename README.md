# NEON — маленькая терминальная экосистема

Три программы с общим паролем, общим оформлением и общим хранилищем данных:

| Файл | Что делает |
|------|------------|
| `neon.py` | лаунчер: вход один раз и меню всей экосистемы |
| `Neonotes.py` | заметки: создание, чтение, дополнение, поиск, редактор, удаление |
| `NeonTodo.py` | задачи: приоритеты, сроки, статусы, статистика |
| `NeoPass.py` | пароли: шифрованное хранилище, генератор, буфер обмена |
| `neoncore.py` | общее ядро: пути, цвета, ввод, авторизация, атомарная запись |

Внешних зависимостей нет — только стандартная библиотека Python 3.10+
(проверено на Python 3.14).

## Быстрый старт

```bash
cd ~/Documents/code
python3 neon.py
```

При первом запуске создаётся профиль с паролем из старой версии Neonotes —
`Ilovepelmeni759`. В настройках хранится уже не сам пароль, а соль и хеш
PBKDF2-SHA256; стартовое значение остаётся в `neoncore.py` только для
первого запуска. Сменить пароль: **neon.py → Настройки → Сменить общий
пароль**. При смене хранилище паролей автоматически перешифровывается, а
рядом остаётся резервная копия `vault.neon.bak-*`.

Каждую программу можно запускать и отдельно:

```bash
python3 Neonotes.py
python3 NeonTodo.py
python3 NeoPass.py

# или сразу нужный раздел через лаунчер
python3 neon.py notes
python3 neon.py todo
python3 neon.py pass
```

Полезные флаги:

```bash
python3 neon.py --where      # где лежат данные
python3 neon.py --version    # версия
```

## Где лежат данные

По умолчанию:

```
~/.local/share/neon/notes/      заметки (.txt)
~/.local/share/neon/todos.json  задачи
~/.local/share/neon/vault.neon  шифрованное хранилище паролей
~/.config/neon/config.json      соль и хеш общего пароля
```

Можно перенести всё в свою папку (удобно для флешки или тестов):

```bash
NEON_HOME=~/neon-data python3 neon.py
# данные будут в ~/neon-data/data и ~/neon-data/config
```

Файлы создаются с правами `600`, папки — `700`.

Не удаляйте `~/.config/neon/config.json`: без него вход сбросится на пароль
по умолчанию, а старое хранилище паролей останется зашифрованным прежним
паролем.

## Что именно защищено

* Общий пароль — это «дверь» ко всем трём программам.
* Заметки и задачи лежат обычным текстом: пароль их не шифрует.
  Это осознанно — так их можно читать любым редактором и грепать.
* Хранилище NeoPass шифруется целиком общим паролем:
  `scrypt` для ключа + HMAC-SHA256 в режиме счётчика + HMAC для проверки
  целостности. Всё на стандартной библиотеке, без `cryptography`.
* Пароль не хранится в настройках: только соль и PBKDF2-хеш. Стартовое
  значение по умолчанию остаётся в `neoncore.py` и работает до смены пароля.
* Криптосхема самодельная и не проходила аудит. Для настоящих секретов
  лучше KeePassXC, а это — учебно-практичная вещь.

Если файл `vault.neon` повреждён или пароль забыт, данные не восстановить;
резервные копии `vault.neon.bak-*` шифруются тем паролем, который был на
момент копирования. Их можно удалить вручную, когда новый пароль проверен.

## Мелочи, которые приятно использовать

* Один вход на весь сеанс: лаунчер передаёт разблокированную сессию
  дочерним программам внутри процесса, повторно пароль не спрашивается.
* `Enter` в выборе номера отменяет действие.
* В многострочном вводе строка с одной точкой `.` завершает текст.
* Поиск в заметках подсвечивает совпадения и ищет по именам файлов.
* Задачи сортируются по статусу, приоритету и сроку; просроченные краснеют.
* NeoPass умеет генерировать пароли и копировать их через
  `wl-copy` / `xclip` / `xsel` (что найдётся).
* `NO_COLOR=1 python3 neon.py` отключает цвета.

## Установка команды `neon`

Файлы уже исполняемые (shebang `#!/usr/bin/env python3`). Можно сделать
симлинк в `~/.local/bin`:

```bash
mkdir -p ~/.local/bin
ln -sf ~/Documents/code/neon.py ~/.local/bin/neon
```

Проверьте, что `~/.local/bin` есть в `PATH`. Для fish:

```fish
fish_add_path ~/.local/bin
```

Для bash:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
```

После этого достаточно команды `neon`.

## Резервная копия

```bash
cp -a ~/.local/share/neon ~/.config/neon ~/neon-backup-$(date +%F)
```

В конфиге только соль и хеш пароля, самого пароля там нет. Но хранить его
вместе с данными всё равно удобнее: при восстановлении сохранится и доступ
к старому хранилищу.

## Как расширять

`neoncore.py` даёт готовые `menu`, `ask`, `confirm`, `choose`, `multiline`,
`header`, `pause`, `atomic_write_text`, `read_json`, `write_json`, `NeonError`.
Новая программа — это файл с `main()`, который вызывает
`core.require_login()` и свой цикл меню; затем добавьте её в `APPS` и меню
`neon.py`. Хорошие кандидаты: дневник, трекер привычек, pomodoro-таймер,
менеджер закладок.
